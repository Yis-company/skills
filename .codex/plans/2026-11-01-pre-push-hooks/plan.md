## Implementation sequence

1. Add an executable tracked `.githooks/pre-push` and a small repository-owned installer, called from a root `prepare` script while preserving any existing lifecycle commands. The installer resolves Git's actual hooks directory, makes an idempotent link to the tracked hook, and refuses with a clear error if a different existing pre-push hook or configured `core.hooksPath` would be overridden or bypass protection. Handle missing Git metadata (such as a source archive) explicitly and document that no hook was installed. Do not change global Git configuration. A normal fresh clone followed by `bun install --frozen-lockfile` must install it; test actual Bun lifecycle behavior, including repeated installs. Fail on installation errors rather than silently claim protection.
2. The hook runs from the repository root, clears Git's local environment variables before child checks, and fails on a missing tool or any failed command. In order: `bun run skills:check`, `bun run typecheck`, `bun run test --exclude scripts/release-with-changesets.test.ts`, `bun run lint`, `bun run format:check`. Use the existing scripts without changing application behavior or reducing CI coverage. Explicitly document the excluded integration fixture, prerequisites, generated file and working-tree nature of checks.
3. Set the existing Turbo `typecheck` task to `cache: false` so web generation and typechecking always execute locally and in CI, including when the ignored generated file is absent or stale. This uses the existing task graph; it adds no cache service, hashing, producer, Turbo dependency, or infrastructure. It may increase CI and local time. No other task's caching changes.
4. Leave `.github/workflows/check.yml` protections intact: full `bun run check` (including the excluded integration suite), both site builds, Docker Compose validation and image build remain CI responsibilities. No live services, DB setup, external integrations, site builds or E2E enter the default hook.
